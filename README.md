# 靱公園「失われた時間を探せ！」v0.1

第一版是坐着体验的开发原型。共用故事和事件，手机使用摄像头图像追踪；Quest 3使用WebXR透视、手柄交互和实验性卡片身份识别。回游模式、GPS和现实景物识别尚未实现。

## 运行

在此目录打开终端：

```sh
python3 -m http.server 5173
```

电脑打开 http://localhost:5173。Windows也可以使用 `py -m http.server 5173`。不要双击HTML运行。

手机与Quest打开真正的HTTPS网址，不能用普通的局域网HTTP地址调用摄像头。默认不显示Debug；开发时打开 `/?debug=1`。无需相机检查流程可打开 `/?preview=1&debug=1`。进度仅存在本次页面会话，不自动同步设备。

## 部署Vercel

把本目录内容放到GitHub仓库根目录，Vercel导入仓库，Framework Preset选择Other，不设置Build Command，Output Directory使用根目录。部署后使用HTTPS链接制作二维码。当前没有自动连接你的GitHub/Vercel账号，也没有创建线上部署。

## 使用

从 `print.html` 按100%倍率打印五张圆形卡。按日時計→春→夏→秋→冬→同一张日時計的顺序识别。第一版通过按钮触发时间恢复，再领取碎片。失去卡片时手机版隐藏AR内容，再次识别恢复显示，进度保持。扫描错误季节不会推进。初次进入先讲解规则，再开始识别。

## Quest 3的实际边界

- 在Quest Browser打开HTTPS网页，选择Quest，随后点击「透視ARに入る」。进入XR后用左右Touch手柄射线点击提示面板下方的按钮。暂未实现裸手捏合交互。
- WebXR透视与访问原始摄像头是不同能力。代码请求 `facingMode: { exact: 'environment' }`，若设备不提供实景摄像头则明确报错，不用avatar摄像头代替识别。
- Quest的卡片识别接入MindAR Controller作为**身份触发器**。舞台放置在XR空间固定位置，尚未实现卡片姿态到Quest空间的标定，也不能声称内容贴在实体卡片上。
- 当前环境没有实体Quest，不能确认指定OS／Browser版本是否提供所需相机流，也未验证44mm实体卡的识别率。必须实机验收。
- 手机上的摄像头参数为通用估计，位置跟踪效果还要在不同iPhone/Android上验证。
- Quest暂不提供GPS与户外回游。

## 模块

- `js/game.js`：纯游戏状态、五个地点、进度和文案。识别来源仅调用 `recognize(spotId)`。
- `js/character.js`：无贴图、无骨骼的程序化小H。共享几何，原始／宇航服两个分组；简单挥手、漂浮、庆祝。
- `js/stage.js`：轻量舞台、虚拟雕像剪影、季节粒子、碎片、XR空间提示。
- `js/tracking.js`：摄像头生命周期和图像追踪。手机使用识别姿态，Quest只使用识别身份。
- `js/app.js`：入口、设备差异、UI、Debug。
- `assets/cards/targets.mind`：五张卡的预编译识别数据，顺序必须和game.js一致。
- `compile.html`：修改卡片后在桌面浏览器重新生成识别数据，并替换targets.mind。
- `vendor/`：固定版本的A-Frame 1.5.0（MIT）和MindAR 1.2.5（MIT），运行不依赖CDN。保留第三方许可文件。

## 当前视觉初稿

日時計使用原插画＋可移动的虚拟影子和两个人物剪影，未对原图雕像抠图和补背景。春花／夏水／秋叶／冬雪是轻量几何粒子表现，不是最终定稿。小H是正面图参考下的程序化近似，尚待你确认比例。没有导入旧50MB模型。

## 分阶段验证

1. 无摄像头预览：完整故事、重复扫描保护、4个碎片、返回日時計与结尾。
2. 手机HTTPS实机：权限拒绝与重试、五张44mm打印卡、光照与倾斜、卡片丢失恢复、刷新与退出。
3. Quest实机：透视会话、左右手柄、相机许可、实际卡片识别、AR退出和重新进入。
4. 完成以上后再加入GPS、导航与现场目标识别，不复制游戏逻辑。

运行逻辑测试：`npm test`（无需npm install）。
